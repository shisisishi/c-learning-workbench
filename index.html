顽固坑清单

每一条都是你或你老师课件里真实出现过的。忘了怎么写的时候来这查。

症状 / 报错原因正确写法
输入 358 却输出 0 scanf 的格式串里写了普通字符，用户必须原样敲进去才行 提示用 printf；scanf 里只留 %d
printf("please input data:\n");
scanf("%d", &a);
📖 课件 chap02 第 34 页：「尽量不要出现普通字符」
输入 9.5 输出 0.000000 写成了 %If（大写 I），不是 %lf（小写 L）。这两个字母在很多字体里长得一样 scanf("%lf", &x);
编译器会警告：use of 'I' length modifier with 'f' type character
1/2 得到 0 整数除整数，小数被直接砍掉（不是四舍五入） 让一边带小数：5.0/9 或 5/9.0
实测：5*(100-32)/9 = 37，但 5/9*(100-32) = 0
5.0 % 2 编译报错 % 求余只能用于整型 求余只用整数；5%6=5，9%4=1，100%4=0
阶乘算出来全是 0 累乘的初值写成了 0 累加初值 0，累乘初值 1
sum = 0; / product = 1;
error: 'fact' was not declared in this scope 用了自定义函数但忘了写声明；编译器是从上往下读的 在 main 前面加 double fact (int n);
或者把整个函数定义搬到 main 前面
函数定义了却报一堆错 分号位置搞错 声明末尾有 ;，定义末尾绝对不能有 ;
结果数字对，但评测判错 输出的文字、空格、换行和样例对不上 照样例一个字符都不差地抄。评测机常做严格比对
if (x = 5) 条件永远成立 = 是赋值，== 才是判断相等 判断相等一律写 ==；= 的左边必须是变量
程序"卡住"不往下走 多半是 scanf 在等你输入，或者格式串要求你打特殊文字 看 scanf 的格式串里有没有普通字符；确认它要的输入格式
中文输出变乱码 Dev-C++ 5.11 默认按 ANSI(GBK) 存文件 现阶段先只用英文输出；中文单独处理
cannot open output file ... .exe 上一次运行的黑窗口还开着，exe 被占用 关掉那个黑窗口再编译

格式控制符对照表（最容易错的地方）
数据类型printf / scanf 都用例子
int%dscanf("%d", &n);
float%fprintf("%f", x);
double%lf ← 是小写 Lscanf("%lf", &x);
char%cscanf("%c", &ch);
保留 n 位小数%.2f / %.0fprintf("%.2lf", avg);
一句话记牢 格式符写错，编译器不拦你，但结果是错的。 所以一定要开 -Wall。
scanf 的三条铁律
  1. 变量前面必须加 &（取地址符）—— scanf("%d", &a);
    漏了它，数据不知道往哪存，轻则乱码重则崩溃。
  2. 格式串里不要写普通字符 —— 写了就必须由用户原样敲进去。
    提示信息用 printf，不要塞进 scanf。
  3. 格式符、个数、顺序必须和变量一一对应 —— scanf("%d%lf", &a, &x);
运算符与优先级
优先级运算符结合方向
高单目 + - ++ --从右向左
双目 * / %从左向右
低双目 + -从左向右

实测：-5 + 3%2 = (-5) + (3%2) = -4　·　 3 * 5 % 3 = (3*5) % 3 = 0

函数的三段式（chap02 §2.5） 
double fact (int n);        /* ① 声明：告诉编译器有这么一个函数，末尾有分号 */

int main (void)
{
    result = fact(i);       /* ② 调用：把 i 交给它，用 result 接住返回值 */
    return 0;
}

double fact (int n)         /* ③ 定义：真正写它怎么算，末尾没有分号 */
{
    int i;  double product;
    product = 1;                                     /* 累乘初值 1 */
    for (i = 1; i <= n; i++) { product = product * i; }
    return product;         /* 把结果回送 */
}
声明定义
末尾分号必须有绝不能有
作用只告诉编译器「有这么个东西」写出真正怎么算
能不能省能（把定义搬到 main 前就不用）不能

命令行调用新编译器时的一个坑 直接调 …\RedPanda-CPP\mingw64\bin\g++.exe 会 exit 1 且一个字都不输出。 原因：g++.exe 自己在该目录下所以能找到 DLL，但它调起的 cc1plus.exe 在 libexec\gcc\…\ 下， 找不到 libwinpthread-1.dll → Windows 报 STATUS_DLL_NOT_FOUND（退出码 -1073741515）。
解法：把 …\mingw64\bin 加进 PATH 再调。 在 IDE 里点 F11 不受影响（IDE 自己会设 PATH），只有命令行才需要管。
