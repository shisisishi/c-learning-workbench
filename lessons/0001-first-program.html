让程序跑起来

你的第一个 C++ 程序：从三行代码，到屏幕上的字

本课的胜利条件 在 Dev-C++ 里按下 F11，屏幕上打印出你自己写的一句话。 就这一件事，做完本课就通关。大约 15 分钟。

为什么先学这个，而不是先学语法

你的作业最后要交一个 .cpp 文件，但老师真正检查的是：它能不能编译、能不能跑出正确答案。 所以在你学会任何语法之前，必须先打通这条路： 

你写的 hello.cpp  ---[ 编译 ]--->  hello.exe  ---[ 运行 ]--->  屏幕上出现一行字

这条路上的每一个环节你都要亲手走一遍。走通之后，你写下的每一行代码都能立刻看到结果—— 这条"改了就能看到"的回路，才是让你学会 C++ 的东西。没有它，写代码就是盲写。

先搞懂：C++ 程序是怎么变成"能跑的东西"的

你写的是人能读的文本，电脑只认 0 和 1。中间需要一个翻译官，叫编译器。

Dev-C++ 不是编译器。它是把「编辑器 + 编译器 + 按钮」打包在一起的壳，叫 IDE。 真正干活的编译器在 Dev-C++ 安装目录下的 MinGW64\bin\g++.exe， 版本是 TDM-GCC 4.9.2。知道这一点有用：以后报错信息里出现的东西，都是这个程序在说话。

所以一次"跑程序"其实分成两件事，Dev-C++ 给了它们两个不同的键：

阶段做什么快捷键产物
编译把你的 .cpp 翻译成可执行文件F9hello.exe
运行执行那个 .exeF10屏幕上的字
一步到位编译 + 运行，连着做F11屏幕上的字

这三个键不是我从网上抄的，是从你这个 Dev-C++ 版本自带的帮助文件里读出来的： Dev-C++ 自带帮助里的 Help\Subjects\Compiling.htm。可以在本机安装目录里打开核对。

程序的三段骨架

所有 C++ 程序都有这个骨架。现在不用理解每一处的细节，先认识它们各自在干什么：

#include <iostream>          // ① 把"输入输出工具箱"拿进来

int main() {                // ② 程序的入口，从这里开始执行
    std::cout << "Hello, C++!" << std::endl;   // ③ 往屏幕上打印一句话
    return 0;               // ④ 告诉系统：我正常结束了
}
  • ① #include <iostream> —— iostream 是 input-output-stream（输入输出流）的缩写。 这行是"借用工具"，不写它，后面的 cout 就不认识。
  • ② int main() —— 程序的入口。系统运行你的 .exe 时， 第一件事就是找名叫 main 的函数，从它的第一行开始往下执行。没有 main，程序无法启动。
  • ③ std::cout << "..." —— cout 是 character output（字符输出）。 把 << 想象成一个漏斗：右边的东西顺着漏斗倒进 cout，最后倒到屏幕上。
  • ④ return 0; —— 向系统报告"我正常结束了"。0 表示没有错误。
关于 std:: 这个前缀 std:: 的意思是"标准库里的"。很多教材会写 using namespace std; 来把这三个字母全省掉， 效果完全一样。你在这门课里可以照着老师/课件的写法来，两种都能编译通过。 本工作站默认写 std::，因为你这个 Dev-C++ 自带的模板就是这么写的。
关于 endl 和 \n 两个都是"换行"。std::endl 除了换行还会立刻把内容推出去（这一课你用不到这个区别）。 现在你只要记住：想让下一句话另起一行，就写 std::endl。
注意是字母 l，不是数字 1——这是新手最经典的错。

动手：八步

下面每步做完点一下该行，会打勾。第 8 步才是重点，别在第 7 步就停。

  1. 双击桌面上的 Dev-C++ 图标打开它。 你的界面是英文的，所以下面菜单名我全部保留英文。
  2. 新建源文件：菜单 File → New → Source File，或者直接按 Ctrl+N。 会出现一个空白编辑区。
  3. 把下面这段一个字符一个字符地敲进去： 
    #include <iostream>

int main() {
    std::cout << "Hello, C++!" << std::endl;
    return 0;
}
    别复制粘贴。手敲一遍，你会顺便记住分号、引号、尖括号各自长什么样—— 这些细节以后全是错误来源。
  4. 保存（这一步最容易翻车）：File → Save As（或 Ctrl+S）。 文件名填 hello.cpp，Save as type 选 C++ source files (*.cpp)。
    后缀必须是 .cpp Dev-C++ 是靠文件后缀决定用 C 还是 C++ 编译器来编译你的代码的 （这是它自带帮助里写的）。存成 hello.c，它就当 C 语言编译，你的 C++ 代码会报一堆错。
    建议存到单独的作业文件夹里，不要和课件混在一起。
  5. 编译：按 F9。下方 Compiler 标签页会滚出一堆字， 最后一行必须是 Errors: 0（0 个错误）。
    不是 0 就直接跳到最后的踩坑清单。
  6. 运行：按 F11（编译并运行，一步到位）。会弹出一个黑色窗口。
  7. 看到 Hello, C++!。
    为什么窗口没有一闪而过 因为 Dev-C++ 自带一个 ConsolePauser.exe 帮你把窗口按住了。 所以你不需要写 system("pause");——那是老教程里的做法， 连 LearnCpp 都明确建议避免它。到这里你已经跑通了一个 C++ 程序。
  8. 改一个字，再按一次 F11。把 "Hello, C++!" 里的内容改成你自己的名字， 重新跑一遍，看输出变了没有。
    这一步才是本课的核心 你刚刚建立了"改代码 → 立刻看到变化"的反馈回路。 接下来每一个知识点，你都可以用这条回路自己验证一遍——这比听讲有效得多。

检验一下

先别往上翻。凭刚才的理解答，答错比答对更有价值——答错说明这里正是需要再想一遍的地方。

Q1int main() 在整个程序里扮演什么角色？

Q2std::cout 的作用是什么？

Q3这句里的 std::endl 起了什么作用？

合上这一页，凭记忆写一遍

这是本课唯一需要"背"的东西，但它不是背文字，是背结构。 拿起笔，或者在 Dev-C++ 里凭记忆敲一遍——不要看上面。

写出一个能打印 Hello 的完整 C++ 程序。写不出来就多试 30 秒，实在写不出再揭开。 

#include <iostream>

int main() {
    std::cout << "Hello" << std::endl;
    return 0;
}

对不上没关系，重点是想不起来的那一处——那就是你下次要留意的地方。 四段结构记住了吗：借工具箱 → 找入口 → 输出 → 报告结束。

踩坑清单

下面每一条都是新手真的会撞上的。撞上了不要慌，回来对照：

症状原因怎么改
报错里说 cout was not declared 忘了写 #include <iostream>，或者漏了 std:: 补上这两处其中之一
报错说 end1 was not declared 把 endl 的字母 l 打成了数字 1 改成 endl
报错提到 _main 找不到 没有名为 main 的函数，或拼错了 检查 int main() 有没有写、有没有拼错
报错说 cannot open output file ... .exe 上一次运行的黑窗口还开着，.exe 被占用 关掉那个黑窗口，再编译
编译报了一大堆看不懂的错，指向你的中文 源文件编码问题。Dev-C++ 5.11 默认按 ANSI(GBK) 存文件 本课先只用英文。中文输出单独处理，我们后面专门讲
黑窗口一闪就没了 不正常。可能是杀毒软件拦截，或 ConsolePauser.exe 被杀掉了 告诉我，我帮你查
一个坏习惯，现在就别养成 网上（尤其 CSDN 上的老帖子）会教你加 system("pause"); 来解决窗口闪退。 不要用。它的毛病包括：依赖 Windows、在别的机器上行为不一致、拖慢程序。 你的 Dev-C++ 本来就自带 ConsolePauser 解决这个问题，所以这个补丁根本不需要。

有问题就问我

我是你的老师，卡住就喊我，不用自己硬扛。
特别欢迎这几类问题：
  • 「我这里报错了」——把完整的报错文字发我（直接复制，别截图，别只发最后一行），我来判断。
  • 「这句为什么这样写？」——任何一行，包括 std::、<<、分号。
  • 「我想要它输出别的，该怎么改？」——最好的学习方式，你出题我来陪你试。
  • 「太快了/太慢了」——节奏不对直接讲，我会调。
