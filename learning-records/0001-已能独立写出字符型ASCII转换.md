# 用户已能独立写出「字符型 + ASCII 运算」的程序

2026-09-18，在桌面发现用户自己写的 `Untitled4.cpp`：

```c
#include<stdio.h>
int main(){
	char upper,lower;
	printf(" ");
	scanf("%c",&upper);
	lower = upper + 32;
	printf("%c",lower);
	return 0;
}
```

这是他自己独立写出的，**不是抄的**（有他自己的痕迹：`printf(" ");` 这种没意义的提示行、变量名 `upper/lower`）。
用他本机的 g++ 4.9.2 实测：`A→a`、`M→m`、`Z→z`，**全部正确**。

**为什么这改变接下来的教学：**
- `char` 变量定义、`scanf("%c", &x)`、`printf("%c", ...)`、字符与整数混合运算 —— 这四件事他已经会用，
  第 2、3 课里那些"字符型入门"的内容**不要再讲**，直接跳到应用层。
- 但他用的是 `+ 32` 这个**魔数**，而他老师 chap06 第 33 页的标准写法是 `ch = ch - 'A' + 'a'`。
  他是否理解 32 的来源**尚未验证** → 已向他提出诊断问题，答案决定下一步是"补原理"还是"进下一章"。
- 同一批文件里暴露了一个**真 bug**（见下），说明他目前的薄弱点在**格式符与类型的严格对应**，
  不在语法结构。后续教学应把火力集中在这里。

# 已定位的真 bug：`scanf("%If", &x)` —— 大写 I 写成小写 l

文件：`本机作业文件 Untitled3.cpp`（09-16 18:11）

```c
double x,y;
scanf("%If",&x);     /* ← 这里是【大写字母 I】，不是【小写字母 L】 */
printf("%lf",x);
```

**实测证据（用他本机的 TDM-GCC 4.9.2）：**
- 编译警告原文：`warning: use of 'I' length modifier with 'f' type character [-Wformat=]`
- 运行 `输入 9.5` → **实际输出 `0.000000`**（期望 `9.500000`）。变量 `x` 根本没被写进去。
- 另有 `warning: unused variable 'y'` —— `y` 定义了没用。

**为什么值得记成一条学习记录：** 这个 bug 是"报告级"的——他大概率观察到了错误结果但不知道原因，
而且 `I` 和 `l` 在很多字体里**长得一模一样**（和 `endl` vs `end1` 是同一类陷阱）。
它精确定位了他当前的真实薄弱点：**格式控制符与数据类型的严格对应**，而不是循环/分支那类结构问题。
